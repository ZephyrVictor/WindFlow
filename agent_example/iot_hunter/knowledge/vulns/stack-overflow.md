# 漏洞类型：栈溢出验证方法论（saved LR/PC 控制）

## 适用特征

静态主张：无界收集/拷贝循环（stbx/memcpy/strcpy 无长度检查）→ 帧布局含 saved LR/PC，声称"偏移 N 控 PC"。目标 = 动态证明 PC 可控（不必然完成 ROP）。

## 症状

- 首枪按静态偏移发 payload **不崩**（HTTP 200 / 错误串应答）——两种可能：静态高估，或存在静态未记录的**运行时前置**
- 崩了但 PC 是垃圾值——不能区分"受控覆写"与"随机破坏"

## 解法

### 隐藏运行时前置排查法（首枪不崩时的正确动作）

1. **不要直接判静态高估**。先反汇编复走数据流，找分支前置条件——重点两类：全局标志/模式字节（rehost gate 补丁语境下常已消解）、**运行时资源检查**（fd ≥ 0、socket connect 成功、文件存在）
2. 实证案例：ap3g3 webauth 栈溢出的 memcpy 分支前置 = hostapd socket fd ≥ 0（全局 [0x31008] 初值 -1，connect "/var/run/hostapd"）——静态复现路径漏了它，真机 webauth 模式下天然满足，**不构成可达性降级**，但 rehost 里必须先解锁
3. 解锁方法：用已实证注入原语在 guest 内可逆制造前置（syslogd 替身 + `/dev/log` 符号链接 → connect 成功），**验证后清理并确认回基线**（重新探测服务正常 + 错误串逐字节回原样）
4. 错误串是路径指纹：memcpy 分支应答 37B `{"originalurl":"","authorized":false}` vs 错误分支 21B `{"status": "ERROR"}`——串口 + 应答体双重确认分支真实执行

### 偏移定位：边界二分

- **下界对照**：N-1 字节（LR 未动）→ 必须不崩，200 正常
- **部分覆写**：N+2 字节（只覆 LR 高 2 字节）→ SIGILL/SEGV 但 PC 高位保留（libc 基址）——佐证偏移
- 目标长度 N → 全量覆写

### 双图样差分（PC 可控铁证）

同长度两枪，只换尾部 4 字节图样：

```
908×A + "PPPP" → 崩溃 PC = 0x50505050
908×A + "ZZZZ" → 崩溃 PC = 0x5a5a5a5a
```

两个图样两个 PC = PC 完全可控，排除随机崩溃。**单图样崩溃不足以主张 PC 控制**。寄存器残迹（r4-r11/fp 全部图样值）进一步证实 `pop {r4-r11,pc}` 帧布局字节级吻合。

### 崩溃取证配置

QEMU 内核参数带 `print-fatal-signals=1` → 崩溃寄存器转储直接进串口日志（`PC is at 0x...` + 全寄存器）。看门狗自愈窗口 ≤10s，每枪后做恢复探测（服务 200）再打下一枪。

### 子主张降级纪律

静态的次要主张（如"另一参数通道同长度同效"）复现失败时如实降级"存疑待补验"，记录截断差/异常形态——**不影响主通道结论**，但为补验留下精确线索（如"按截断差 9 字节补偿长度再试"）。

## 死路

- 单图样崩溃 + 写"PC 可控"——不合格，必须双图样
- NX+PIE 下止步于 PC 控制是正常边界，不要夸大为 RCE；ROP/泄露原语属后续工作，报告写明
- 静态"另一通道同效"子主张失败 ≠ 主通道失败——分开判定
