# 漏洞类型：认证绕过/未授权面验证方法论

## 适用特征

静态主张：预认证可达 / 认证缺失 / 调用面绕过（A 端点把请求转给本应认证的 B handler）。目标 = 动态证明绕过路径与边界。

## 症状

- 免认证请求拿到 200——但不知道绕的是认证层还是经由别的调用面
- rehost 后全部 401——分不清环境异常与目标真的安全

## 解法

### 401 差分定位（调用面绕过 vs 认证缺失）

同 payload、无凭据、两个端点对照：

```
直打 /oeap/config_set_ssid.cgi（真端点）   → HTTP 401 + WWW-Authenticate（串口零 sink 活动）
经 /testfastcgi.cgi（调用面）转投同一 handler → HTTP 200 + sink 执行 uid=0
```

结论形态：**绕过经由调用面（testfastcgi 把 params 传给 entry[19]），而非 /oeap/ 认证缺失**——两者的修复建议完全不同（前者删/锁调用面，后者修认证层）。curl -v 全文确认 0 处 auth 头，排除"忘了带凭据"误判。

### 认证缺失枚举（面级主张）

逐服务/逐 method 调用，判据 = **无鉴权挑战即达 handler**（不是"有响应"，要看 handler 侧行为证据——sink 调用/数据读写出现在串口/日志）。明文 listener + 零 TLS + 零 interceptor 的静态主张，动态判据 = 任意 method 调用无 401/握手挑战直达。

### 认证边界对照矩阵

预认证主张必须配对照组：同请求打"已知需要认证的端点"验证认证机制本身在环境里是**工作的**（否则"绕过"可能是环境把认证弄坏了）。环境契约写明哪些路由无认证、哪些有（inventory §4 逐项核对）。

### 环境异常排查链（rehost guest 里 401 全拒时，按序执行）

1. sha1 比对 guest 内运行的二进制/配置/htpasswd 与镜像原件逐字节一致性（debugfs 挂 image 只读侧读）
2. 同套文件搬到宿主 qemu-user（qemu-arm-static）复跑认证——过了 = 二进制没问题，差异在插桩内核
3. URI 绕过枚举（大小写/%2f/双斜杠/../）排除绕过误判
4. 结论定性"环境异常，非目标漏洞相关"，静态主张标"未被推翻"

## 死路

- "无凭据 200 = 绕过成功"不成立——必须先证明认证机制在环境里工作（对照组 401）
- rehost 自建凭据文件（如自建 htpasswd）时，"厂商默认凭据链"主张**不可成立性验证**——如实裁剪，不要硬测
- 默认开关状态（服务是否监听）是运行时前提，动态结论只证明"开启时可达"，前置写清
