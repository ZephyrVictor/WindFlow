# 项目文档

这里维护项目的长期上下文。文档是架构讨论与开发计划的可追踪记录，不是临时笔记。

## 推荐阅读顺序

1. [`architecture.md`](./architecture.md)：当前架构和约束。
2. [`development-plan.md`](./development-plan.md)：当前阶段、任务和验收标准。
3. [`decisions.md`](./decisions.md)：已经确认的架构与技术决策。
4. [`discussions.md`](./discussions.md)：讨论过程、结论和待确认问题。

每次开发前至少阅读前两项；涉及架构或技术取舍时，再阅读后两项。规则详见 [`.codex/agent.md`](../.codex/agent.md)。

## 文档职责

| 文件 | 记录内容 | 更新时机 |
| --- | --- | --- |
| `architecture.md` | 当前有效的模块、边界、数据流、运行和质量约束 | 架构稳定或实现使架构发生变化后 |
| `development-plan.md` | 阶段目标、任务、优先级、验收标准和风险 | 计划调整、任务开始或完成后 |
| `decisions.md` | 重要取舍、备选方案、影响和决策状态 | 做出或废弃不可逆/高影响决策时 |
| `discussions.md` | 讨论议题、结论、未决问题和行动项 | 每次形成可复用结论后 |

## 当前状态

项目刚完成文档骨架初始化，业务需求、技术栈、部署目标和团队约定仍待确认。未确认内容必须保持为 `TBD`/`待确认`，不能被当作实现依据。
